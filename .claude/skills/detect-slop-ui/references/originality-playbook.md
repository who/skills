# Originality through product decisions

Use these methods as extensions of the ten-tell critique. Derive a design from the actual product instead of treating the catalog as a list of banned styles.

## Establish a design thesis

Fill in this private working sentence from evidence:

> Help [audience] do [primary task] using [content structure], with a character drawn from [specific brand or domain cue]. Express it through [two or three concrete decisions].

Separate established facts from assumptions. Look for distinctive nouns, domain artifacts, user priorities, content shapes, and existing assets. Use these to choose what deserves space and emphasis. Apply the substitution test: if a recommendation still fits an unrelated product after changing the logo, make it more specific.

Choose coherent constraints, such as one clear focal area, stable data alignment, or color reserved for meaningful state. Derive constraints from this product; never impose the same number of colors, fonts, cards, or decorative elements everywhere.

## Choose structure before style

| Information or task | Candidate structure | Reason to choose it |
|---|---|---|
| Compare many records | Table, aligned list, or compact grid | Shared columns make differences easy to compare |
| Follow steps or time | Sequence, itinerary, calendar, or timeline | Position expresses order or duration |
| Browse independent objects | Cards or gallery | Each item has a useful identity or visual preview |
| Resolve exceptions | Prioritized queue with detail view | Urgency and next actions dominate |
| Read and understand | Article or document hierarchy | Measure and pacing support comprehension |
| Manipulate a real object | Object-centered workspace | Tools stay connected to what they affect |

Do not recommend a table if the task depends on visual browsing, or a timeline if order is irrelevant. Keep cards that earn their boundaries. Do not sacrifice mobile use or established workflows for a desktop composition.

## Translate identity into observable decisions

The following are illustrative possibilities, not themes to reuse automatically:

| Product context | Possible source of character | Concrete consequence |
|---|---|---|
| Campus timetable | The daily schedule and institution's existing identity | Give time, room, next class, and real schedule changes priority; reduce ornamental welcome space |
| Incident operations | Runbooks, logs, and exception triage | Place active incidents and response actions ahead of decorative KPI cards; preserve meaningful severity colors |
| Recipe workspace | Mise en place, recipe notation, and cooking sequence | Group quantities with ingredients; connect steps to ingredients; give timers purposeful emphasis |
| Portfolio | The creator's actual work and point of view | Let projects, artifacts, and concise captions determine the rhythm instead of an interchangeable hero |
| Finance analysis | Comparisons, time series, and uncertainty | Align numbers and units; show provenance and relevant time; reserve emphasis for meaningful changes |

Translate a proposed direction into the decisions the user would actually see:

- **Hierarchy and composition:** identify the main object or action, what moves, what shrinks, and what becomes secondary. Give a specific screen mapping rather than "use asymmetry."
- **Typography:** specify the roles and relationships first. Preserve good existing fonts; choose a new family only when it changes the experience for a reason.
- **Color:** map each changed role to a purpose. Preserve real category/state colors. Suggest exact values only when useful and label untested contrast.
- **Surfaces and shape:** say which relationships need a boundary, fill, shadow, or radius. Avoid a universal flattening pass.
- **Copy:** use the product's nouns and action verbs. Match tone to the audience. Delete self-evident explanations and unsupported claims.
- **Imagery and marks:** use actual work, product artifacts, or existing brand assets where useful. Do not recommend random art as a substitute for hierarchy. Respect asset and licensing constraints.
- **Interaction:** use motion to explain change, orientation, or feedback. Keep persistent information quiet. Preserve reduced-motion behavior and familiar controls.

For a broad redesign, make alternatives differ in composition, density, and emphasis, not merely color. Recommend one based on the main task and available evidence. Prefer a focused fix if the current identity is already sound.

## Make recommendations reviewable

Use a concrete before/after format. These are hypothetical examples, not facts to insert into a product:

| Before | Possible after | Acceptance criterion |
|---|---|---|
| A working task app's large "Supercharge your productivity" banner | Compact "Tasks" heading and the existing task controls | The primary list and creation action are visible earlier at the same viewport |
| Different decorative gradients on every report tile | Shared neutral surfaces and the existing meaningful status labels | Readers can distinguish status without learning arbitrary color meanings |
| Every course rendered as a large accent-edge card | Time-aligned class rows, retaining room and instructor details | Each class's time and location can be scanned without repeated large containers |
| "Live" badge with unknown behavior | Verify the state source, then use a factual status or remove decoration | The displayed state corresponds to an observed, meaningful product state |
| Identical generic sections across a portfolio | Work samples determine the page's sequence and proportions | The page communicates the creator's actual work before generic self-description |

For each chosen change, provide the exact affected region/component, the proposed adjustment, impact and effort, and one observable criterion. If source is available, identify the owning component or token; if only a screenshot is available, use spatial and textual anchors. Never fabricate file names or line references.

## Avoid replacing one template with another

- Keep established accessibility, semantic HTML, keyboard access, readable copy, and predictable navigation. Familiar affordances are useful.
- Keep meaningful categories, status indicators, and selection states. Originality does not require reduced information.
- Keep whitespace proportional to the task. A dense tool can be deliberate; sparse marketing layouts are not the universal goal.
- Use visual restraint deliberately. Do not make minimalism a rule or add arbitrary irregularity to simulate human authorship.
- Preserve a user's explicit brand preferences. If they require gradients, glass, emoji, or a familiar font, improve their use in context.
- Challenge boilerplate hero/feature-card/testimonial sequences only when they fail the actual content or journey. These are additional review patterns, not extra tells attributed to the source article.
- Treat invented metrics and decorative security claims as factual issues. Replacing their visual treatment does not fix the unsupported claim.

## Verify the revised result

Judge the change against the original task and the stated criteria:

1. Can the intended user identify the main object and next action?
2. Does hierarchy survive long content and relevant screen sizes?
3. Do color, borders, badges, and motion communicate consistent meaning?
4. Does copy describe this product accurately and omit irrelevant construction details?
5. Do affected focus, hover, selected, disabled, loading, empty, error, and success states remain clear?
6. Is the visual character attributable to this product's content, audience, or brand?
7. Have unnecessary treatments been removed without losing useful information or familiar controls?

State exactly what was inspected. Where execution or measurements are unavailable, distinguish a proposed check from a verified result. No aesthetic audit can guarantee that every viewer will regard a design as original.
